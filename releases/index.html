    Version History¶

    All releases are available on GitHub Releases.

    Latest Release¶

    v1.26.1 - 2026-11-11

    WSPR decodes every cycle again: from v1.24.2 to v1.26.0 the WSPR page decoded the first cycle after it opened and then nothing. The WSPR search is a third faster. The web spectrum follows your dB range, TX power is a slider in the Radio menu, and the web top and bottom bars are cleaned up.

    Fixes

    • ⛔ WSPR decodes every cycle again (Samuel W7STF). From v1.24.2 to v1.26.0 the WSPR page decoded the first cycle after you opened it, then logged NO MEMORY for the candidate search for every cycle after that, so it looked like a bad antenna or a dead band. The receiver now takes all the memory it needs once, when you open the page, and allocates nothing during a cycle. If the memory is not there, the page says so once, with the numbers. On the bench: 22 cycles and repeated page re-entries with no failure, against 4 failures in 4 cycles on v1.26.0.
    • The WSPR search is a third faster: 8.3 s instead of 12.8 s. While the WSPR page was showing, the Tab5 kept drawing the hidden panadapter behind it and took about a third of the processor the decoder runs on. That time now goes to decoding, two searches per cycle.
    • A memory leak on every visit to the WSPR page is fixed (16 KB a visit). The same fault, smaller, is fixed in the WiFi scan, WiFi on/off, the Reader page, the QMX terminal and the Bluetooth start. The firmware build now refuses this fault.
    • The web spectrum follows the dB range (Samuel W7STF). The browser drew the spectrum on its own fixed scale and ignored the floor and ceiling set on the Tab5. It now uses them (with F off, as on the Tab5).
    • The web WSPR page shows only the controls that work there. Mode, BW, Zoom, Tune and RIT did nothing on the WSPR page, or were refused, and are no longer shown. Band stays and lists the WSPR bands: a pick does what the WSPR page's own band button does.
    • The FT8 boot self-test says SKIPPED, not FAIL, when it cannot get memory - for example when the Tab5 starts straight into the WSPR page. It used to report that as a decoding fault.

    Web page

    • TX power moved from the top bar to the Radio menu, as a slider with one stop per level your Calibrate Power sweep measured - 0.1 W steps where the radio has them. The top bar no longer scrolls sideways.
    • The top bar's frequency and S-meter, and the bottom bar's clock, are smaller. The bottom bar shows the WiFi network name; the signal strength is in its tooltip. Miscellaneous is now Misc.
    • The bottom-bar menus are never taller than the window; on a short window a menu scrolls instead of losing its top.

    Documentation

    • The Web DSP chapter link on tab5.lav.dk works again, and the site now publishes itself on every release.

    Known, not fixed

    • One capture showed the first CW message after a QMX power cycle held by the radio for 33 seconds and then sent ahead of the next one. It has not been reproduced and the cause is not known.
    • The web audio stream carries 1 to 3 short holes a second (11 ms each) when the Tab5's WiFi is busy. With noise reduction on, the browser patches them.

    Previous Releases¶

    v1.26.0 - 2026-11-10¶

    Noise reduction and an auto-notch in the browser, at no cost to the Tab5. Each band remembers its frequency and its mode across a restart. The CW page gets a Log button, a STOP for queued text, type-ahead sending from the browser and a band guard on every send.

    • Web DSP: a speech model and a spectral noise reduction, and an auto-notch, all in the browser.
    • Each band remembers its frequency and mode across a restart.
    • CW: type-ahead from the browser, a STOP for queued text, a Log button on both screens, a Station row on the web.
    • CW sent from the Tab5 passes the band guard; with no IARU region set, CW send is refused.
    • Fixes: a web spectrum that could stay dead for a session, a frame written into the next web reply, web commands over 255 bytes.

    v1.25.0 - 2026-11-09¶

    The MODE: CW page is now also on the web, at parity with the Tab5. The CW page's band-plan fence covers the Digi sub-band too, on both screens — and closes the one gesture (a spot tap, from the browser) that could still tune outside it. Contest logging, manual callsign entry, and an automatic sidetone fix.

    • The MODE: CW page in the browser: tap-to-send macros, free text, macro editing, the General/Contest toggle and a contest name.
    • Contest logging: CONTEST_ID and the serials actually sent and received.
    • Manual callsign entry on the CW page's station card.
    • The CW page's band-plan fence covers Digi as well as CW, on both screens, and the web's tuning paths now honour it.
    • The sidetone's Absolute/Relative setting switches itself on entering and leaving the CW page.
    • RBN and DX cluster spots moved to periodic polling.
    • Fixes: the last character of a macro shown as received, a jumpy pinch-zoom, dead Zoom/Tune controls on the FT8 top bar, the web grey-list view.

    v1.24.2 - 2026-11-04¶

    WSPR decoding dead after a visit to FT8 is fixed for good. Two new CW page controls: a TX offset shortcut and Semi QSK break-in delay. A pileup crash and an RRR bug fixed. Plus a one-frame screen flash, found and fixed the same night it was introduced.

    • WSPR could stop decoding entirely after a visit to the FT8 page, for the rest of the session — a PSRAM fragmentation issue, now fixed for good.
    • CW TX offset, from the CW page itself, and a numeric keypad for the WPM number.
    • Semi QSK — the radio's CW break-in delay — exposed in the settings drawer.
    • A new {SERIAL} macro and an {RST} placeholder for CW macros.
    • Fixed a crash from clicking into an FT8 pileup, and WAIT_RPT reading a bare RRR as a signal report.
    • esp_hosted's SDIO driver now survives a failed memory allocation instead of crashing the device; a full SD card can now recover on its own; the SD browser now mutes the Tab5 speaker during a file transfer.

    v1.24.1 - 2026-11-03¶

    A two-fix patch on v1.24.0: an FT8 CQ-answer reboot, and a manual pounce that held on a station that had actually signed off.

    • Fixed a reboot when answering a CQ caller on FT8 (Randy N4OPI, Rick Trommer W5NR). Tapping a station calling CQ could crash the Tab5 with a stack overflow; replying to CQ was the one path affected. Auto Answer CQ and calling CQ yourself were never affected.
    • A manual pounce now lets go of a busy target that signed off with RRR, not only RR73 or 73 (Gyula HA3HZ). Many stations close a QSO with a bare RRR and no separate 73; that was read as still busy, so a target who was actually free kept holding your pounce.

    v1.24.0 - 2026-11-03¶

    A MODE: CW page, as a beta, and an internet radio player for when the bands are quiet. Audio and binaural CW graduate out of beta. Two-finger pinch now pans while it zooms, on both the Panadapter and the CW page.

    • MODE: CW, as a beta. A dedicated CW page: the radio's own decode ticker with squelch for a quiet band's endless lone Ts, a copilot hint line that says what the copy meant, a station card, and two named macro sets - General and Contest - switched by a toggle at the bottom of the panel, placed there and away from the memory buttons on purpose so it cannot be mis-hit while working them. Keying the radio over CAT is confirmed working, off air. There is no abort for a message in progress - both RX; and a mode bounce were tried on the bench and neither stops an in-flight send, so a macro runs to completion once started. The page ships on as this release's own beta; turn it off with cw_page_enabled = no or {"action":"cw_enable","on":false} if you would rather not have it yet.
    • Web Radio. An internet radio player on the Tab5 - search and genre filter over the radio-browser.info directory, six memory slots (tap plays, long-press stores), the station's live ICY title, and playback that keeps running in the background after you close the player. Decoded on the Tab5; the QMX and its I/Q are untouched.
    • Audio, and binaural CW, are no longer a beta. First shipped in v1.16.0; tried, reported on, and settled.
    • Two-finger pinch now pans while it zooms, on the Panadapter and the CW page. It always computed a pan from how far the midpoint between your fingers moved, but handed it to the same function a zoom-preset button uses - which recentres on the passband and threw the pinch's own pan away every time. Fixed: the pinch gesture now keeps the pan it computed. (Known rough edge: the pan is live, not a local preview like one-finger drag, so a fast two-finger drag can look like it jumps on this hardware rather than glides - correct, just not smooth yet.)
    • Pinch-zoom and one-finger pan now work on the CW page too - previously restricted to the Panadapter page from before the CW page existed. The CW page's own macro buttons are excluded from the gesture so a press-and-hold there cannot wake the spectrum underneath.
    • Three-finger hold toggles CW's own Simulation Mode, the same gesture FT8 already used for its simulator.
    • A genuinely real trailing letter on a quiet band is no longer lost. The CW decoder's noise squelch could hold a real E or T forever if nothing settled it before the band went quiet - "CQ TTTTTTTT DE" rendered "CQ D". A time-based flush now releases it after a short wait with nothing new arriving.
    • The diagnostic log on the SD card now keeps its history, instead of deleting it (Michael K Johnson KZ4LY). It used to rotate at 5 MB and throw away the previous generation, about 10 MB total regardless of card size. It now moves into a history/ folder on rotation and is only pruned, oldest first, once the card's free space drops under 50 MB.
    • A manual FT8 pounce now gives up on a busy target immediately, the same as the robot already did (Gyula HA3HZ). It used to wait roughly 7.5 minutes before moving on; nobody had actually decided an attentive operator should wait that long for a station it can see is mid-exchange with someone else.

    Audio graduating out of beta does not include the 3.5 mm line-in path, which is still a declared beta - nothing has been decoded through it yet. The alternate JS8 speed added in v1.23.0 remains default-off and unproven on air.

    v1.23.1 - 2026-10-31¶

    Five controls the Tab5 had and the browser did not: zero-beat, CW keyer speed, RIT park, output power and SSB auto-tune. A finished QSO no longer claims the other station never answered. And a boot where WiFi fails to start can no longer take the device down.

    • Zero-beat from the browser, CW keyer speed from the top bar in CW, park/restore a RIT offset, transmit power per band from the browser, a finished QSO no longer stuck saying the other station never answered, and a WiFi-start failure that could abort the device on boot is fixed.

    Audio and binaural CW were a declared beta at this release; see above.

    v1.23.0 - 2026-10-30¶

    Right-drag pans the spectrum, in the browser and with a BLE mouse on the Tab5. The JS8 panel shows stations, the conversation and a type box all at once. Spur suppression works for the first time since it was written, and the FT8/JS8 decoder is 2.2x faster.

    • Right-drag pans the spectrum. Hold the right mouse button on the spectrum or waterfall and drag sideways to move the window along the band; the dial does not move. Left-drag still tunes, so the two do not collide - left moves the radio, right moves the view. The browser had no pan at all before this, and the same gesture works on a BLE mouse connected to the Tab5.
    • The JS8 panel shows all three panes at once (Ryan KK6DZB): stations, the conversation, and a type box you compose in. The Stations and Conversation tabs are gone, and so is the old Free text button - there is nothing left to switch between. With a physical keyboard you type in place; without one, tapping the box opens the modal composer so the on-screen keyboard does not cover it. The browser shows the same three.
    • Spur suppression had never worked, and it was walking the dial up the band (Steve KX7R). The 25 Hz offset it nudges the dial by is not on the QMX's 10 Hz grid, so every nudge was rounded and four callers waiting for the frequency to read back were left waiting.
    • The S digit of the report you received is measured (Gyula HA3HZ). In the Log a contact window, Tab5 and browser, it comes from the S-meter's own 10-second peak hold instead of being a 9 every time. R and T stay at the mode default, and the report you send is untouched - that is your judgement of a signal this device cannot hear.
    • A WWFF, IOTA, GMA or WCA activation called CQ POTA. Five programmes were added in v1.22.0 and this one site was not swept, so each went out under the wrong programme's name. Each now carries its own token; WWBOTA does not fit FT8's four-character modifier, so a bunker activation goes out as a plain CQ rather than as something untrue.
    • A finished QSO stopped reporting "Busy: working ..." forever (Bruce N9JCV).
    • The off-view marker arrow works. It exists in the browser now as well as on the Tab5, appears on both edges, is gated on the marker and the bandwidth, and is actually tappable - the tap used to be swallowed by the spots lane's edge counter.
    • The spectrum no longer jumps when you pan. The waterfall is re-anchored and the spectrum average re-seeded when the view moves, so the content crossfades instead of snapping. The settle check meant to do this never ran above zoom x1.
    • The passband dims while you drag it, in every mode. It used to vanish, and only in CW.
    • A crash class is closed. One unlocked table in the WiFi co-processor's RPC layer was behind two different field asserts. It has run 20 hours clean here; the previous failures came within 7 minutes of boot.
    • The FT8 and JS8 decoder is 2.2x faster. One of its two monitors had its hottest buffer in a 32 KB region the system calls internal RAM but which is far slower to reach than cached PSRAM, and that buffer is copied twice per block, 93 blocks a slot. Both monitors now sit at 881 and 877 ms where one was 1968 ms - about seven points of one processor core returned on every FT8 and JS8 slot.
    • Hamlib rigctld is documented at last (Brian KB9WFS). The Tab5 has been a Hamlib NET rigctl server on port 4532 since v0.9.6 with nothing in the manual about it. There is now a chapter, including Brian's own QLog recipe, and the limit nobody had written down: it cannot key the radio. There is no set_ptt, so set PTT to none or VOX and key the QMX the way you normally do.
    • The "no decodes for 20 minutes" message no longer blames the radio. On a quiet band, telling you to power-cycle the QMX is simply wrong - and a wedged radio and an empty band look identical to this firmware. It now says the band is most likely quiet and that leaving it receiving is the right thing to do, keeping the power-cycle hint conditional on a flash you have not cycled for.

    ⚠ One alternate JS8 speed can now be decoded alongside the one you are using, one slot in five, off the audio the normal slot already captured. Default off, and not proven. It is receive-only by explicit refusal: a decode reaches the conversation pane tagged with the speed that heard it and nothing else - never the stations list, the QSO machine, the robot, transmit arming, PSK Reporter or the clock sync. No real station on another speed has ever been decoded with it, only my own encoder. Decoding all four speeds at once measures 118% of one processor core and does not fit.

    Audio and binaural CW remain a declared beta.

    v1.22.0 - 2026-10-28¶

    CW and SSB contacts can be logged by hand on the Tab5 and in the browser; activation covers seven ?OTA programmes and writes each one's own ADIF file on stop, with the contact count on its own button; a Scheduled events pane puts the contest calendar and the ?OTA schedule on one timeline. FT8, FT4 and JS8 each keep their own frequency. Fixed: dial writes quantised to 10 Hz, the waterfall no longer shows history from before a WSPR or FT8 visit, five of the seven activation programmes could not be selected, and several browser faults reported by Randy N4OPI. RF gain relabelled to say what it actually acts on.

    v1.21.0 - 2026-10-25¶

    CW-Tune (long press the bandwidth to land on the nearest CW signal) and a narrow audio peak filter on the CW pitch; peak hold on the spectrum; RF gain and an AGC row in the audio panel; server mode (the Tab5 stops drawing and just serves the web page); the left-edge swipe became a page picker. Fixed: CW audio arrived up to 60 Hz off the dial on units with a calibration trim, the Smoothing slider ran backwards and the browser never applied it, the Diagnostics page was refused by its own guard, and a crash in the WiFi co-processor driver after a command timeout.

    v1.20.5 - 2026-10-23¶

    The spectrum and waterfall on the Tab5 were throwing away part of what they had already computed, and I had not known it. Plus a round of fixes and ergonomics from your reports.

    • The Tab5 spectrum and waterfall now show you everything they decode (Samuel W7STF). Sam reported the spectrum stalling briefly on the Tab5 while the same picture in a browser stayed smooth. Measuring it properly turned up something worse than a display quirk: fourteen of every hundred spectrum frames were being computed and then silently discarded, and about a third of all waterfall rows with them. The drawing code waited twenty milliseconds for the display and gave up, while the display routinely holds it for a hundred and eighty. A lost waterfall row is a missing line of history, not a repeated one — the operator could see it as a 10 rows/second setting behaving like 5. The trace also reaches the screen about twice as often as before, and the display no longer spends frames redrawing numbers it has already shown. ⚠ It is better, not solved: what remains is how unevenly the display itself refreshes, which is also why the browser still looks smoother — it repaints sixty times a second against ten frames of data, and the Tab5 cannot.
    • The waterfall rate setting now moves the waterfall you are looking at (the operator). On the web page the control only ever changed the Tab5's carpet; the browser drew one row per received frame whatever it said. Both screens follow it now, using the same arithmetic, so they agree. The stream is a fixed ten frames a second, so ten is the ceiling of genuinely new rows — 20, 30 and 40 scroll faster by repeating the newest row, on both screens alike, and the setting's help text now says so instead of implying they add detail.
    • ⛔ A CW keying command could transmit without the band check. The check added in v1.20.3 reads the firmware's own source to find transmit paths, and KY — the command that sends CW text — was not recognised as one of them. It is now, so keying from outside the firmware is refused where the band plan does not allow it. Found here; nobody reported it.
    • POTA and SOTA: the contact count was counting every activation you had ever made of that park (Bruce N9JCV). Activate the same reference on a second day and the panel opened already showing the first day's contacts, and saying the park was activated before you had worked anybody. POTA counts per UTC day, so that is what it counts now.
    • Your CQ says POTA while an activation is running (Bruce N9JCV). It did not, so nobody hunting parks knew you were in one. Field Day mode has always done exactly this — switch it on and every CQ goes out as "CQ FD" without being asked — and an activation simply was not using the same mechanism. It sends "CQ POTA" (or "CQ SOTA") for as long as the session is running, and goes back to normal when you stop it. Nothing to set, nothing to put back.
    • Tapping somebody who answered your CQ now works straight away (Don WB0LQW). It used to say "Busy: calling CQ" and make you stop the CQ by hand first, by which time the caller had often given up. Answering a caller is the whole point of having called CQ, so the CQ stands down and the exchange starts. Tapping a second station while you are already mid-contact with a first still refuses — dropping a half-finished QSO without being asked is a different thing.
    • The stations you skipped are listed, and you can take it back (Randy N4OPI). On the web FT8 page, under the grey-list line. Each call clears on its own as well as all at once. It is a separate list from the grey-list on purpose: that one is the software setting aside a station that cannot hear you, this one is your own decision, and one button should not quietly undo both.

A WSPR transmission keys the radio for about 110 seconds out of every 120 - an FT8 burst is about 12 - and running a QMX flat out on that cycle puts sustained heat through the PA transistors. QRP Labs warn about exactly this in the QMX manual, and the radio's own built-in WSPR beacon turns its PA down for the same reason. The Tab5 now does the same: it sets the QMX's Max. PA voltage to about 6 V for as long as WSPR transmit is enabled, and restores your setting afterwards. Measured on a QMX at 12 V: 5.4 W -> 1.6 W out, and 76% less heat in the finals.
    • You can always see which state you are in. The control is a full-width button reading green "ON - about 1 W" or red "OFF - FULL POWER, finals at risk". Turning protection off takes two deliberate taps; turning it back on takes one. While it is off the TX block on the WSPR page reads FULL PWR in red.
    • ⚠ It reduces the heat in the finals; it does not remove it from the radio. The excess is dropped inside the QMX instead, so total heat fell only 18% in the same measurements. If you intend to beacon for hours, feed the radio from a lower supply - the QMX accepts 6.0-12.0 V, and around 9 V leaves far less to throw away as heat. That is the one thing no firmware setting can do for you, and it is now in the manual.
    • Declared power is advised by measurement. During each transmission the Tab5 asks the radio what it is actually producing and shows the answer under the setting. Switching protection on or off also moves the declared figure to the value that setting normally gives. Both are suggestions - the number is a claim about your station and stays yours to choose. The list runs to 37 dBm again: a declared power never commanded the radio, so limiting it could only have prevented an honest declaration.
    • The FT8 Options checkboxes are easy to hit (Don WB0LQW). The touch target was the small box alone, a tap that drifted a few pixels was swallowed by the panel behind it, and the word beside each box did nothing. The touch area is much larger now, the tap cannot be stolen, and tapping the word toggles the setting.

    • The station you are working never disappears from the list. With Show only CQ callers on, your own exchange vanished — two filters were stacking. The contact in progress is now exempt from all of them. (Roy KI0ER)
    • Leaving Radio menus hands the radio back properly. After a menu visit the waterfall could misbehave until you paused and resumed by hand; closing the terminal now does that for you. A QMX's IQ mode is session state that a trip through its own menus can drop. (Roy KI0ER)
    • A pileup caller is answered from what they actually sent rather than always a bare report — the last of a family of bugs where the manual Transmit button was right and the automatic path lagged.
    • The clock no longer says UTC(GPS) on a radio with no GPS. The Tab5 decided a radio was GPS-disciplined when its second-tick agreed closely with internet time — but the Tab5 also sets that clock on a radio without GPS, so it was reading back its own handiwork. Measured across four pushes, the agreement landed anywhere from 12 ms to 834 ms, so the same firmware would say GPS on one unit and not on another for no reason at all. It was not only a wrong label: once it believed there was GPS it stopped keeping that radio's clock right, and a QMX loses its clock every time it is switched off. The dial agreed with the radio but the waterfall did not, and tapping a signal tuned you about 30 Hz off — so you transmitted off frequency as though XIT were on. The radio's CW offset was read once, when the Tab5 connected, and never again, so changing it on the radio left the display correcting by the old figure for the rest of the session. It is now re-read every few seconds while you are in CW. (Roy KI0ER)
    • A caller who answers your CQ with a report instead of a grid is followed properly. Someone who already knows they have you often skips the grid and reports you straight away; the reply should acknowledge that with R plus your report, not send another bare report and lose a cycle. Tapping Transmit by hand always did this correctly — it was only the automatic run that was a step behind. (Gyula HA3HZ)
    • A dated, day-at-a-time ADIF export. A Today only, dated file link beside the ADIF download gives just that day's contacts, named qso-YYYY-MM-DD.adi, so a daily file already says which day it is. (Gyula HA3HZ)

    v1.8.2 — 2026-08-13¶

    Your radio's own spurs can be removed from the display, and a POTA clock that stopped being stolen.

    • The spurs your radio makes itself can now be taken off the display. If you have ever seen evenly spaced signals that are always in the same place, do not move when you tune, and are still there with the antenna unplugged — those come from the QMX's own synthesizer. On the bench at 14.074 MHz, the FT8 calling frequency, the strongest sat nearly 40 dB above the noise floor. For a net or a round robin where one station is off frequency, the offset comes and goes as the turn passes, without re-dialling it. The button reads RIT (+250) while an offset is parked. (Roy KI0ER)

    • The band strip no longer vanishes when you are out of band. It reads "Out of band" in one flat colour and comes back to normal as soon as you are inside a band, so the row is never just empty and the coarse-tune drag stays where your thumb expects it. (Samuel W7STF)

    • The panadapter no longer switches your radio off trying to fix something it cannot. After certain restarts the QMX stops answering on USB until it is power-cycled.     v1.7.0 — 2026-08-09

    A mouse, the phone spots that were missing, and knowing who hears you.

See Live Spots.

    • Who is hearing me. Asks PSK Reporter which receivers have copied your callsign, listing distance, bearing and the report they gave you.     • Steadier decode list during CQ runs: stations you can't currently hear (they transmit when you do) no longer vanish mid-run, and the list keeps entries for 2 minutes instead of 1
    • Display sleep: set an idle timeout and the screen turns off while everything keeps running (FT8, radio link, web UI). Tap to wake — the wake tap can't press anything. Two-finger double-tap blanks immediately. A real battery win for unattended and web-only use
    • Reorganized settings drawer: setup items (WiFi, callsign, band-plan region, brightness, battery care, display sleep) grouped at the top, display-tuning controls below
    • Web page polish: the bottom bar's many buttons are now three tidy menus (QSO Logs / Files / Miscellaneous); a congested WiFi link can no longer freeze the page for seconds
